# 知识维护与自然语言纠错

正式规则需要适用对象、来源版本、负责人、范围、条件、例外、生效/失效和实际认可证据。公开方法和AI标签先为候选；个人偏好不冒充公司政策。编辑报告措辞不自动修改规则。

用户指出错误后，先保留问题、旧答案、引用和版本，核查：原件是否过期/冲突，提取是否缺失/错位，检索是否找错范围，规则是否不适用，计算或回答是否错误，执行是否与提案不同。反馈是调查线索，不自动是真值，不修改正确原件迎合用户。

## 有界修复

只改错误层及受影响依赖。提取修复不改政策，口径修订不改交易事实，来源撤回后有关引用失效。冲突先看适用范围与权威，不机械选最新日期。没有足够证据时将受影响结论降为待核实，保留其他成果。

保存原历史、修复理由、范围和实际产物；检查当前调用路径已经使用新内容。再验证原问题、相关未见题和边界例，新会话从文件恢复复测。只改聊天里的答案不能称修好。修复失败保留真实状态及可继续入口。

本地workspace_index的candidate/active/needs_review/retired是独立附属规则状态，不能写入旧rule_card枚举。旧契约的draft/pilot/active等状态按原schema维护，使用时明确映射；active也不意味免审、自动写入或权限扩大。代码检查approval_ref存在不能证明批准人有权，Agent须核查真实证据。

将同质审核问题合并为明确对象快照、数量、条件和建议，例外独立。负责人确认一次且条件未变时复用决定；来源、对象版本、金额、收件人等关键条件变化则重新判断原决定是否适用。

资料发现、ZIP边界、私有术语与可复用报表定义见 [资料发现与私有口径](discovery-and-context.md)。先核范围和已有决定，再做本页步骤；来源/提取/指标/规则/产物/动作分别登记依赖。

## 案例与分层依赖

任务结束先查同对象/适用条件案例，更新已有项或新增。记录问题、条件、证据、尝试、实际结果、失败反例、复核人/待复核、复查日期；客户文章与内部排错分开，去掉不必要身份。一次成功或一次投诉不能升格政策。

私有Records可把 source→extraction→metric/definition→rule/report→artifact/action 分层绑定修订。`observe_file`记录获准源哈希，读取有效状态时重新核该文件；工具不会擅自寻找未授权路径。人工编辑源、ZIP新增成员或公式更改会改变哈希；改tool_version需明确修订提取记录，下游变stale。撤回使依赖链restricted，停止引用，不自动删除历史。若只是值里写普通path/sha256而未使用file_ref，宿主必须自行核源并登记变更，不应声称工具已自动检查。

Records的历史不是工作成果；结果文件通过Workspace保存，替换前读人改并带实际expected_hash。Records和Workspace不是跨文件事务，崩溃后分别检查孤立文件及记录；工具状态不能替代新会话实际任务复测。

独立审查后的限制优先级：撤回沿固定历史版本和当前依赖链保守传递，优先于本地文件改版、丢失和其他stale分支。get/read/history展示入口逐历史版本遮蔽restricted正文，历史文件仍保留原内容，不是安全删除或企业访问控制。后来依赖的撤回也可能使旧链路保守受限，不能解释为当时必然使用过该来源。

仍受限记录不能通过修订删除来源来恢复。有效/过期记录移除依赖或替换file_ref来源路径须提供provenance_change_ref，说明独立重做的证据；同一路径重新核哈希登记新版本可正常继续。证据字符串只用于审计，宿主必须验证真实性；不能把原文换标签冒充独立来源。
