# 从可用流程延展自动化

先验证当前业务流程，再判断重复、稳定、可核验的步骤是否值得复用。人的最佳保留环节可以是创意、政策、争议或专业决定，不以无人化为统一终点。

约定触发、输入范围、规则版本、步骤、人工例外、允许动作、结果核验和失败恢复，再补负责人、运行宿主、在线时段、预算、通知及停止条件。实际调度用现有获准环境；Skill本身不常驻。建议、创建、启用、提交、完成分别报告。

## 动作的身份与结果

投递ID、业务事件ID、对象版本和动作ID分开。相同通知不重复业务，不同通知也不一定代表不同事件。动作关联对象、当前版本、参数哈希、批准快照和外部查询方式；幂等保证绑定提供者、接口版本、保留期和参数条件，不能仅设永久true。

单独的动作附属状态采用proposed、awaiting_action_authorization、ready_for_authorized_executor、submitted、execution_unknown、verified_executed、business_closed、failed_known。旧execution_record枚举保持不动：旧executing映射提交/进行中；旧outcome_unknown或另一套pending_unknown映射execution_unknown；旧succeeded_verified映射verified_executed。历史其他别名按真实语义映射，不把所有“成功”都当业务关闭。

版本、主体、金额、目标或授权过期时旧批准不放行。服务端条件写/对象锁等需真实工具支持；脚本在写前读一遍不能保证没有竞争。actions.py仅检查记录一致性，不能证明真实批准人身份，也不执行外部动作。

## 恢复和覆盖

未知超时先查询原任务或对象；无法确定且重复有后果时暂停该动作，不能盲目换键重试。批量逐对象记录结果，下游依赖未完成不能算成功，重试只处理明确需要者并再核当前条件。

事件可能乱序、重复或丢失。保存接收和业务时间、完整覆盖边界及缺口，使用有界回看和周期对账。最新记录不是全量完成；迟到数据更正报告，但补算模式关闭业务写出口。

检查手动、定时、子流程等入口，调度器限并发不代替对象级保护。权限撤回、预算边界、严重错误或外部状态不明时停止受影响部分并保存进度。通知聚焦需要人行动的变化、重要完成或故障，别用不变状态刷屏。

接口受理、系统对象创建、审批、实际可用和业务方接受分别留证据。已发信、已支付、已出库等不承诺回滚；补救另按系统能力和授权处理。没有实际执行时，只交提案与限制。

## 逐对象事件与交接

`ledger.Ledger`是可选离线事件账本，没有外部执行器。事件ID重复且内容相同则忽略，不同则拒绝；乱序旧序号不回退状态，跳号先核事件。未知先查，已验证不重放；撤权只阻断相应对象，其他项进度保留。receipt字段只记录回证，无法证明真人职责或真实账号成功。模拟必须把证据标为simulation，不能写成账号验收。

交接记录使用当前scope、共同对象ID/期间、最小来源快照、任务/等待项、预期成果、责任人/待定、接收条件和各方回执。`received`、`accepted`、`executed`、`closed`放在附属handoff.value中分开登记，不改旧契约枚举。不接受和未回执项保持未决；采购、收货、发票和付款各有自己的ID和关系，消息条数不是订单数。

schedule记录区分定义保存、真实任务创建、运行、失败通知、取消及实际核验。只有真实宿主创建回执和试运行才支持“已运行”；无账号时保持not_run。保存报告定义或模拟定时不创建任务。重算仅更新文件，不重发邮件、采购、退款或付款。周期运行需单独确认对象、时段、预算、通知和停止方式。
