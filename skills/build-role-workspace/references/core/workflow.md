# 从岗位资料完成工作

先确定这一次要支持什么决定、交什么结果及已有资料。用户已说清时直接处理。既有资料不足以决定目标时提出具体候选，不要求用户设计应用架构。

三层通过稳定ID和版本关联：原件及观察事实 → 适用方法、规则和案例 → 当前任务及交付。结果可以产生新的事实或候选经验，但不会自动变成正式政策。成功和失败案例同样保留，明确适用限制。

原11阶段仍是业务阶段：intake、workflow_mapping、rule_elicitation、sample_calibration、working_result、workflow_acceptance、automation_assessment、automation_build、completed_manual、completed_assisted、ready_for_scoped_run。已有材料足以跳过的阶段直接复用；不适合自动化时可在人工或辅助完成状态结束，不继续询问RPA配置。

## 最小带做循环

读取一个具体案例及已有标准，提可纠正的候选，问一个真正改变判断的问题，同时保存整理结果。下一轮只补新出现的条件与反例。初次资料缺失时完成可确认的部分，并说明补哪份证据最可能改变当前决定及取得成本。

先完成真实小成果，再形成可复用约定。一个任务约定包含目标、对象/期间、输入版本、规则状态、允许处理范围、输出位置、验收及剩余问题。模板由Agent填，不发空表给新手。

## 结束与交接

输出可读报告或工作文件，含结论、依据、未知、已做和下一步。接收者没有Skill也应能看懂；仅带对方需要的数据。收到、已读、接受、执行和业务解决分别记录。无权限不能靠换账号绕过。

持久记录至少包含当前目标、角色、阶段、输入清单、有效规则、产物及其来源、人工决定、未决项、下一步与能力限制。新会话从这些文件恢复；没有持久文件就不宣称已经续接。

不要以知识条目数或自动化次数证明价值。记录人实际准备、阅读、判断、修改和维护的时间，机器等待另列。与普通Agent比较时保持任务、资料、模型、工具和预算一致，并保留失败和成本。

资料发现、ZIP边界、私有术语与可复用报表定义见 [资料发现与私有口径](discovery-and-context.md)。先核范围和已有决定，再做本页步骤；来源/提取/指标/规则/产物/动作分别登记依赖。
