# 精确计算与业务报告

先确认业务对象、粒度、单位、币种、时间区间、时区、分母、过滤、去重、归因和成熟窗口。缺字段与零值不同，错误提取先修数据，不为使结果好看改政策。

整体比率从总分子除以总分母：10/100与20/1000合并为30/1100约2.7273%，不能平均为6%。分母为零时结果未知/不适用并说明原因。多标签或多个片段连接不能放大原交易。跨期间、币种或不同指标版本先拆组，不直接相加。

金额使用十进制定点运算，保留原值和规则。无确切匹配依据的多对多关系交人确认，不按同额猜关联。快照与增量、订单应付与实付、支付与退款、平台归因与企业订单分别说明。无退款金额不能凭“退款成功”字段扣掉整单金额，无成本不报利润。

## 从表格到可核验结果

读取真实表头、行数、空行、汇总行、公式及缓存；标明源工作表和行号。以稳定业务ID检查粒度；长数字ID作为文本保留，不转换为浮点。清洗千分位、百分号、时间和缺失标志必须有明确映射，原值不覆写。公式无缓存时说明未计算，宿主有获准表格引擎时再复算。

先核控制总数，再输出结论和差异。若完整性或口径不明确，给有范围的观察结果和补证待办。关联不当因果，预测有基线、假设、验证窗口及局限；全成功样本不能支持普遍成功率。没有人群事实不凭画面猜年龄收入。

## 输出选择

简单定性任务用短文与证据清单，数量比较用表，趋势用图，视频证据用时间线。不要给所有岗位强造同一套KPI或复杂看板。交付文件应先给业务判断，再给依据、口径、未知与下一步，用户可调整输入并重做。

每个建议说明要支持的决定、证据强度、适用条件和最有价值的补充资料。报告保存、写回和对外分享分别核验。晚到数据产生更正版本和影响说明，分析重算不重放已执行业务动作。

## 固定定义、独立复核、可验证决定

重复报表在用户工作区保存report定义：指标/公式/分母、单位/币种、期间/时区、过滤、分组、比较对象、归因和退款成熟窗口、来源版本、展示和质量规则。再次执行先核依赖；数据更新不是自动重放业务动作。

复核总数、隐藏/过滤、重复业务键、关联扩行、汇总行、加权比率、缺失与零值、可比窗口和迟到更正。`quality.relation` 仅预警多对多扩行，不做金额合并；各表先独立聚合到已确认共同粒度。`quality.metric` 根据share/rate/growth区别判定，增长150%不违反占比范围；分母零与缺失分别返回。

`planning.bridge`采用逐商品数量效应 `(实际量−预算量)×预算价` 与价格效应 `实际量×(实际价−预算价)`；数量项包含结构变化，不另套组合公式。单商品10000×50到11000×48，差额28000=50000−22000。它是算术分解，不证明价格或销量变化的原因。不同商品单位先在商品内算金额，同币种同可比口径后才汇总。

补货前先将实际商品件数乘已核配方；`quality.expand_bundles` 将缺件数、未知配方和映射冲突留作unknown，不填零。不能用订单数推采购袋数。`planning.inventory` 只处理已规范化同单位同保护期的情景：确认合格现存、期限内可放行在途、未被扣过的承诺、需求/缓冲依据、交期、MOQ/倍数、预算与剩余可售期。规划期定义为第0日至horizon_days−1日，第horizon_days日到货不能支持本期。每日先收货再扣当日需求；候选量按期间净缺口取整，假设在lead_days日到，不是已求得可执行的到货方案。必须展示整个规划期daily_projection和planning_shortages，既查候选到货前，也查其后其他批次到货前的断档；即使候选量为0也检查。只看prearrival_shortages会漏报中途缺货。约束失败为needs_review；完整也只draft_only。未提供仓容、真实批次分配等时需另核，不宣传最优采购或可下单。

重要建议随附：决定对象、证据、替代解释、候选动作、预期方向、成本、风险、观察窗口、成功/停止条件及负责人/待核。缺证据时给补证成本和最能改变判断的检查，不编百分比收益、默认服务水平或“60天备货”。

均匀日需求情景要求daily_demand×horizon_days等于期间需求，不能把不一致的期间总量塞进每日模型。候选量和时序有缺口时只报needs_review，必须先讨论更早到货、分批或其他有证据的安排，并重新核预算、效期和容量，不能把净缺口当安全下单量。
